## 1. Anthropic Agent Patterns → SOC Agent Roles (AGT)

**AGT-F01 — Orchestrator-worker is the canonical multi-agent pattern and maps directly to a SOC. (High confidence — primary source.)** Anthropic's "How we built our multi-agent research system" (Jun 13, 2025) states: "Our Research system uses a multi-agent architecture with an orchestrator-worker pattern, where a lead agent coordinates the process while delegating to specialized subagents that operate in parallel." A SOC lead/triage agent can decompose an incident and spawn correlation/classification/response subagents. Source: anthropic.com/engineering/multi-agent-research-system (2025).

**AGT-F02 — Anthropic explicitly recommends starting with WORKFLOWS, not autonomous agents. (High.)** "Building Effective Agents" (Anthropic Engineering) draws an architectural distinction: "Workflows are systems where LLMs and tools are orchestrated through predefined code paths" vs. agents that "dynamically direct their own processes." The five documented workflow patterns are prompt chaining, routing, parallelization, orchestrator-workers, and evaluator-optimizer. IMPLICATION: a student SOC should be mostly deterministic workflow with agentic reasoning only where genuinely needed — this is defensible and reduces failure risk. Source: anthropic.com/engineering/building-effective-agents.

**AGT-F03 — Routing pattern → alert triage/severity classification. (High, [INFERENCE] on mapping.)** The routing workflow "drives intelligent routing of inputs to specialized handlers based on content classification." This maps to Tier-1 triage: route alerts to the right investigation path. Source: anthropic.com/engineering/building-effective-agents.

**AGT-F04 — Parallelization → multi-source enrichment/correlation. (High, [INFERENCE] on mapping.)** Parallelization enables "concurrent processing of multiple LLM operations, with their outputs aggregated." Anthropic reports parallel subagents "cut research time by up to 90% for complex queries" and that "the lead agent spins up 3-5 subagents in parallel." SOC mapping: query VirusTotal, AbuseIPDB, GeoIP, and internal logs simultaneously. Source: anthropic.com/engineering/multi-agent-research-system (2025).

**AGT-F05 — Long-context (200K+) log reasoning is a genuine Claude edge. (High.)** Anthropic's process diagram notes "if the context window exceeds 200,000 tokens it will be truncated and it is important to retain the plan," and describes external-memory patterns for long-horizon tasks. Claude models now advertise a 1M-token context window at standard pricing (per Anthropic pricing coverage, 2026). SOC mapping: reason over long log windows without RAG chunking loss. Confidence High that the capability exists; [VENDOR] flag on the "90.2% improvement" performance claim below.

**AGT-F06 — Extended/interleaved thinking is engineering-substantiated for complex correlation. (High.)** Anthropic docs: extended thinking "leads Claude to output additional tokens in a visible thinking process" as "a controllable scratchpad"; interleaved thinking lets Claude "think between tool calls and make more sophisticated reasoning after receiving tool results." CAVEAT [1-SRC/nuance]: the surfaced thinking is a SUMMARY, not raw chain-of-thought (encrypted signatures), so it is an explainability aid, NOT a forensic audit trail. Source: docs (console.anthropic.com/docs/en/build-with-claude/extended-thinking); nuance from developersdigest.tech (2026).

**AGT-F07 — Citations API is the single strongest "genuine edge" for explainable triage. (High.)** Anthropic's Citations feature lets Claude "attach context to its answers based on source documents supplied by the user"; per Anthropic's launch, a customer (Endex) "reduced source hallucinations and formatting issues from 10% to 0%" and Anthropic's internal evals "increased recall accuracy by up to 15%." SOC mapping: every triage verdict cites the exact log line/IOC that justified it — directly answers judges' explainability/trust concern. [VENDOR] on the 0%/15% figures. Source: platform.claude.com/docs/en/build-with-claude/citations; enterpriseaiworld.com (2025).

**AGT-F08 — Structured outputs give validated JSON for downstream automation. (High.)** Claude supports native structured outputs (strict JSON schema) — "Get validated JSON results from agent workflows" — GA for Claude 4.5+ and on AWS Bedrock. CRITICAL CONSTRAINT: "citations require interleaving citation blocks with text output, which is incompatible with the strict JSON schema constraints of structured outputs" — so the team must choose per-agent: cited narrative OR strict JSON, not both in one call. Source: platform.claude.com/docs/en/build-with-claude/structured-outputs.

**AGT-F09 — MCP (Model Context Protocol) is the tool-integration substrate. (High.)** Anthropic ties tool use to MCP servers that "give the model access to external tools." SOC mapping: wrap VirusTotal/AbuseIPDB/SIEM queries as MCP tools/tools-in-a-loop. Source: modelcontextprotocol.io; anthropic.com/engineering/multi-agent-research-system.

**AGT-F10 — Prompt caching materially cuts cost for repeated system prompts / long docs. (High.)** Cache reads cost ~0.1x base input (up to ~90% savings); a large cached system prompt (e.g., the OCSF schema, Sigma ruleset, org playbooks) is reused across every alert. Source: Anthropic pricing coverage (2026).

**AGT-F11 — Multi-agent burns ~15x the tokens of chat; use it only where parallel breadth pays off. (High, [VENDOR] on exact multiple.)** Anthropic: "agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats… multi-agent systems require tasks where the value of the task is high enough." IMPLICATION: don't over-agent; reserve parallel subagents for genuine multi-source correlation. Source: anthropic.com/engineering/multi-agent-research-system (2025).

**AGT-F12 — Anthropic's own eval discipline is a copyable credibility signal. (High.)** They started with "about 20 queries representing real usage patterns" and used LLM-as-judge on factual/citation accuracy. A student team can mirror this with ~20 labeled incidents and an LLM-judge eval — a strong "technical complexity + rigor" talking point. Source: anthropic.com/engineering/multi-agent-research-system.

## 2. Pipeline Feasibility (PIPE)

**PIPE-F01 — Adopt OCSF as the normalization schema; it is the defensible, industry-adopted choice. (High.)** OCSF launched Aug 2022 (IBM, AWS, Splunk, CrowdStrike collaboration) and is "now powered by a consortium of over 660 contributors from 197 enterprises." AWS Security Lake "uses OCSF as the data schema" centralizing data "from 80 sources"; Splunk, CrowdStrike Falcon Next-Gen SIEM, and Elastic all ship OCSF parsers. Sources: databahn.ai (2024), splunk.com blog, aws.amazon.com/security-lake (2024), docs.aws.amazon.com.

**PIPE-F02 — ECS is the mature fallback and is merging into OpenTelemetry. (High.)** ECS "has been around longer than OCSF and is more mature and stable" and "was donated to OpenTelemetry (OTel)," merging with OTel Semantic Conventions. RECOMMENDATION: standardize agents on OCSF for the security-native taxonomy; mention ECS/OTel as the observability bridge. Source: medium.com/snowflake (Berkowsky).

**PIPE-F03 — Log ingestion is feasible with syslog + webhooks + Fluent Bit on free infra. (High, [INFERENCE] on the student-build framing.)** Standard patterns: syslog for host/network devices, webhooks for SaaS/cloud alerts, Fluent Bit as a lightweight forwarder/normalizer. All open-source; runs on Render free tier / local. (Technical documentation permitted under R3 even if undated.)

**PIPE-F04 — VirusTotal free public API: 4 requests/minute, 500/day, non-commercial. (High — primary source.)** VirusTotal docs: "By default it is limited to at most 4 requests of any nature in any given 1 minute time frame"; the public API is "a free service… for any website or application that is free to consumers." Daily cap of 500/day and monthly quotas confirmed. Design implication: hash-first local dedup + 24h caching. Sources: docs.virustotal.com/docs/api-overview; docs.virustotal.com/docs/consumption-quotas-handled.

**PIPE-F05 — AbuseIPDB free tier: 1,000 IP checks/day. (High.)** Multiple corroborating sources: "free tier permits 1000 lookups per day" (nixintel/IPRepCheck) and isMalicious comparison ("Free (1,000/day)"). Source: github.com/nixintel/IPRepCheck; ismalicious.com (2026).

**PIPE-F06 — GeoIP via MaxMind GeoLite2 (free, account required) for enrichment. (High.)** GeoLite2 is the standard free geolocation DB used across SOC tooling. Tavily is available as a sponsor credit for live OSINT/web threat-intel lookups (fits the "knowledge agent" role). (Vendor docs permitted.)

**PIPE-F07 — Detection division of labor: Sigma (deterministic) + statistical scores + LLM only for the hard reasoning. (High.)** Sigma is "an open-source, generic standard for creating and sharing threat detection logic across different SIEMs" (Florian Roth & Thomas Patzke, 2017); the SigmaHQ repo has "more than 3000 detection rules." RECOMMENDED SPLIT: Sigma handles known-pattern detection deterministically (cheap, explainable); statistical/anomaly scores flag outliers; Claude reasons ONLY over correlation, novel-chain narrative, and response recommendation. This split is itself a strong "technical complexity + feasibility" talking point. Sources: sigmahq.io; github.com/SigmaHQ/sigma.

**PIPE-F08 — MITRE ATT&CK auto-mapping has real prior art: TRAM (LLM-based) and RAM. (High.)** MITRE's TRAM "now uses Large Language Model to automate MITRE ATT&CK technique detection"; its LLM classifier "accurately predicts 50 of the over 600 ATT&CK (sub-)techniques." The academic RAM framework (arXiv 2502.02337, 2025) maps structured SIEM rules to TTPs using LLM prompt chaining. IMPLICATION: TTP auto-mapping is credible but bounded — scope to a curated technique set, don't claim full 600+ coverage. Sources: ctid.mitre.org/projects/threat-report-attck-mapper-tram; arxiv.org/pdf/2502.02337.

**PIPE-F09 — Guarded response actions can be SIMULATED safely (firewall block, account disable, host isolate). (High, [INFERENCE].)** For a hackathon, response actions should be executed against a simulated/mocked environment (e.g., a controlled lab VM or stub APIs) rather than real infrastructure — this both de-risks the demo and demonstrates blast-radius discipline. Real products (Dropzone, Prophet) gate the same actions behind human approval (see SAFE section).

**PIPE-F10 — Incident-to-playbook auto-generation has clear prior art in SOAR + AI-guided playbooks. (High.)** Swimlane/TAG Cyber's autonomous-SOC framework includes "AI-Guided Response & Playbook Optimization, where playbooks dynamically adapt to incidents." Auto-generating a runbook/playbook from a resolved incident is a defensible, novel-adjacent feature. Source: swimlane.com/resources (five pillars).

## 3. Autonomy Safety — THE Credibility Hinge (SAFE)

**SAFE-F01 — Human approval for consequential actions is universally required. (High.)** OWASP LLM Top 10 (2025) mandates defense-in-depth "combining input validation with output filtering, privilege restrictions and human-in-the-loop controls for sensitive operations," and recommends "human approval for consequential actions." Prompt injection is LLM01, the #1 risk for the second consecutive edition. Source: genai.owasp.org/llm-top-10 (2025); aembit.io summary.

**SAFE-F02 — Indirect prompt injection via log content is the signature novel threat and MUST be designed for. (High.)** OWASP and multiple arXiv papers (Greshake et al. on indirect injection; arXiv 2603.21642) establish that "an LLM accepts input from an external source… that subsequently alters the LLM's behavior." In a SOC, attacker-controlled strings inside logs (e.g., a crafted User-Agent or filename) can hijack the LLM analyst. Required mitigations: treat all log content as untrusted data (never instructions), clear instruction/data separators, least-privilege tools, deterministic egress blocks, and human approval on actions. Sources: OWASP 2025; arxiv.org/pdf/2603.21642; arxiv.org/pdf/2603.10749 (AttriGuard, 2026).

**SAFE-F03 — Policy-as-code engines (OPA/Rego, AWS Cedar) are the standard guardrail for agent actions. (High.)** OPA is a CNCF graduated project (graduated Jan 29, 2021) that "decouples authorization decisions from application code," returning allow/deny on structured input. It is now explicitly recommended as "the missing guardrail for your AI agents" and for MCP access control (OPA vs Cedar). RECOMMENDATION: put every response action behind an OPA/Cedar policy check (who/what/conditions) — cheap to implement, hugely credible to judges. Sources: openpolicyagent.org; codilime.com (2026); natoma.ai.

**SAFE-F04 — "Levels of SOC autonomy" frameworks exist (self-driving analogy). (High, [VENDOR] — multiple vendor models, no single standard.)** Several 5-level maturity models exist: SentinelOne's Autonomous SOC Maturity Model (Levels 0-4); Cybersecurity Ventures/Stellar Cyber's five SOC types (fully manual → rule-based → AI-unified → AI-augmented → AI-led); UnderDefense's 5-level model with explicit human-involvement percentages (L1 100% → L5 10-15%) and a **Shadow → Assist → Full-Autonomous** rollout (AI recommends only → human approves → acts within pre-approved parameters). USE THIS as the idea's spine: an explicit autonomy dial per action type. Sources: sentinelone.com; cybersecurityventures.com; underdefense.com (2026).

**SAFE-F05 — Commercial products default to human-in-the-loop; "full autonomy" is gated by confidence + policy. (High, [VENDOR].)** Dropzone AI autonomously does Tier-1 triage/investigation but "your team directs, AI agents execute" and containment requires explicit approval; Prophet's "default posture is conservative… It surfaces a recommendation; the human acts on it," with autonomous isolate/reset only "if the confidence score is above 99%." Microsoft Security Copilot shipped agents (Mar 24, 2025) that "autonomously assist" but operate inside Defender/Entra/Intune/Purview with oversight. Palo Alto Networks Cortex AgentiX agents are "bound by the same roles and permissions as your analysts — with human-in-the-loop approval for impactful actions," with "full transparency into an agent's reasoning and planning process"; Cortex EVP Products Gonen Fink: "Unleashing autonomous agents without tight control is a recipe for disaster." IMPLICATION: mirror this exactly — tiered autonomy with confidence thresholds — across four named vendors. Sources: dropzone.ai; nomadlab.cc (2026); thebizaihub.com; microsoft.com/security/blog (2025); Palo Alto Networks Cortex AgentiX.

**SAFE-F06 — Immutable audit trails + rollback are required before automation is trusted. (High.)** OWASP: "Log all inputs and outputs so you can trace what happened after an incident." UnderDefense gates Stage 3→4 on "governance framework, including audit trails, rollback procedures, and human override authority." The team should log every agent decision + the citation that justified it (append-only). Note the AGT-F06 caveat: Claude's thinking summary is NOT the audit record — log the structured decisions and tool calls. Sources: OWASP 2025; underdefense.com.

**SAFE-F07 — CrowdStrike 19 July 2024 is the canonical automation-blast-radius cautionary tale. (High.)** A faulty Falcon "Channel File 291" content update caused an out-of-bounds memory read, crashing Windows machines worldwide. Microsoft VP David Weston (Official Microsoft Blog, 20 Jul 2024) stated: "We currently estimate that CrowdStrike's update affected 8.5 million Windows devices, or less than one percent of all Windows machines." Commentary/RCA analysis attributes escalation to "a lack of phased rollouts — a critical failure in blast radius control"; insurers estimated ~$5.4B cost to US Fortune 500. USE THIS to justify staged rollout / blast-radius limits / ring deployment in automated response. Sources: blogs.microsoft.com/blog/2024/07/20; en.wikipedia.org/wiki/2024_CrowdStrike-related_IT_outages; cisa.gov (2024); techtarget.com.

**SAFE-F08 — NIST SP 800-61 was revised to Rev.3 (Apr 2025), aligning incident response to CSF 2.0. (High.)** NIST SP 800-61r3 "supersedes SP 800-61r2" and reframes incident handling around the CSF 2.0 functions rather than the legacy 4-phase model. Legacy 4 phases (Preparation; Detection & Analysis; Containment/Eradication/Recovery; Post-Incident) remain useful operating context. There is also a Coalition for Secure AI "AI Incident Response Framework v1.0" (Mar 2026). Cite r3 as the current standard. Sources: nvlpubs.nist.gov/…/NIST.SP.800-61r3.pdf (2025); coalitionforsecureai.org (2026).

**SAFE-F09 — CERT-In's 6-hour reporting mandate is the India credibility + urgency anchor. (High — primary source.)** CERT-In Directions of 28 April 2022 (under §70B(6), IT Act 2000, effective 27 June 2022): entities "shall mandatorily report cyber incidents… to CERT-In within 6 hours of noticing such incident." Non-compliance carries penal consequences under §70B (imprisonment up to one year and fine, reportedly raised as high as ₹1 crore). This is a killer justification for automated triage speed. Sources: cert-in.org.in/PDF/CERT-In_Directions_70B_28.04.2022.pdf (2022); trilegal.com; deloitte.com.

## 4. Demo-ability Evidence (DEMO)

**DEMO-F01 — Splunk BOTS datasets are CC0-licensed and contain ready ransomware/APT chains. (High — subagent-verified.)** BOTS v1/v2/v3 datasets, scoring apps, and questions are released under Creative Commons CC0; data is pre-indexed so "there are no volume-based licensing limits" (runs on the free Splunk Enterprise trial). BOTS v1 is built around the fictional "P01s0n1vy" APT vs Wayne Enterprises AND a Cerber ransomware scenario on host we8105desk (malicious macro doc → VBScript → Cerber payload → file encryption). Sources: github.com/splunk/botsv3 LICENSE; splunk.com/…/botsv3-dataset-released (2018); BOTS v1 walkthroughs.

**DEMO-F02 — Atomic Red Team (MIT) covers the full kill-chain with specific ATT&CK IDs. (High — subagent-verified.)** MIT-licensed (© 2018 Red Canary). Coverage: phishing T1566.001 (Spearphishing Attachment) + T1204.002 (User Execution: Malicious File); lateral movement T1021.001 RDP / T1021.002 SMB / T1021.006 WinRM; ransomware impact T1486 (Data Encrypted for Impact, incl. an Akira simulation) + T1490 (Inhibit System Recovery) + T1489 (Service Stop). WARNING: atomics execute real (benign) commands — run only in an isolated lab VM. Sources: github.com/redcanaryco/atomic-red-team (LICENSE.txt; atomics/T1566.001, T1021.006, T1486).

**DEMO-F03 — MITRE Caldera (Apache 2.0) can orchestrate the same ATT&CK chain automatically. (High — subagent-verified.)** Caldera is Apache-2.0 licensed (now github.com/apache/caldera), "an automated adversary emulation system that performs post-compromise adversarial behavior." Good for a live, repeatable attack-generation demo. Source: github.com/apache/caldera; caldera.mitre.org.

**DEMO-F04 — A realistic phishing → initial access → lateral movement → ransomware chain IS replayable from public data/safe simulation. (High — subagent-verified.)** Two complementary paths: (a) investigate pre-recorded data via BOTS v1 (Cerber + P01s0n1vy); (b) generate fresh telemetry via Atomic Red Team (T1566.001 → T1204.002 → T1021.x → T1486) or Caldera in an isolated lab. Both are free and license-clean for a hackathon.

**DEMO-F05 — Additional datasets exist but carry license caveats. (High — subagent-verified.)** CICIDS2017 (CIC/UNB) is free for research but under custom terms with MANDATORY citation and no explicit commercial grant. AIT Log Data Set (Zenodo, CC BY-NC-SA 4.0 — NON-COMMERCIAL, fine for a student hackathon, not for commercialization) contains multi-step attack chains (nmap→nikto→hydra brute-force→webshell CVE-2019-9858→Exim privesc CVE-2019-10149). LANL "Comprehensive Multi-Source Cyber-Security Events" (2015) is public-domain-waived and includes LABELED red-team lateral-movement events — excellent detection ground truth. Security-Datasets (OTRF, formerly Mordor): license ambiguous (MIT badge vs GPL references) — verify the in-repo LICENSE before relying on it. ## 5. Architecture Shapes (ARCH)

Claude API pricing anchor for all cost estimates: **Sonnet 4.6 at $3 / $15 per million input/output tokens; Haiku 4.5 at $1 / $5; Opus at $5 / $25**, with prompt caching cutting cached input ~90% and Batch API 50% off (Anthropic pricing, 2026). A single incident triage of ~10K input + ~2K output tokens on Sonnet ≈ $0.06 before caching; with cached schema/playbooks and Haiku for routing, well under 5 cents/incident. [ARCH-F07, High confidence on order-of-magnitude; individual model version numbers vary across secondary trackers.]

**ARCH-F01 — Shape (a) Copilot-first analyst assistant.** Build effort: LOW (1.5-2 weeks). Wow-factor: MEDIUM (judges have seen chatbots). Failure risk: LOW. Cost: ~1-3¢/query. Verdict: safe but under-scores on Novelty/Complexity. Good as the fallback if the team slips.

**ARCH-F02 — Shape (b) Guarded-autonomy tiered response.** Build effort: MEDIUM-HIGH (3 weeks, tight). Wow-factor: HIGH (the autonomy dial + Shadow/Assist/Autonomous demo is memorable). Failure risk: MEDIUM (must nail the safety story). Cost: ~3-8¢/incident. Verdict: BEST complexity-per-feasibility; directly hits Novelty, Complexity, Feasibility, UX (explainable), and Future-work.

**ARCH-F03 — Shape (c) Autonomy + deception/honeypot integration.** Build effort: HIGH. Wow-factor: HIGH. Failure risk: HIGH (honeypot + LLM classifier is a second system to build; SYNAPSE-style LLM honeypot achieved only ~75% precision / 68% recall per arXiv 2510.25939). Verdict: over-scoped for 3 weeks unless a honeypot is dropped in pre-built; keep as a future-work slide.

**ARCH-F04 — Shape (d) Compliance-first (CERT-In 6-hr + DPDP) autonomous SOC.** Build effort: MEDIUM (reuses (b) + a reporting/audit layer). Wow-factor: HIGH for Indian jury (regulatory realism). Failure risk: LOW-MEDIUM. Verdict: STRONGEST business/impact + India-relevance; best combined as a skin over (b).

**ARCH-F05 — Shape (e) MSSP multi-tenant SOC-as-a-service for Indian SMEs.** Build effort: HIGH (multi-tenancy in 3 weeks is risky). Wow-factor: MEDIUM-HIGH (business potential). Failure risk: HIGH. Verdict: strongest business narrative but too heavy to build; present as the scale/GTM vision, not the MVP.

**ARCH-F06 — RECOMMENDED SHAPE: (b) guarded-autonomy tiered response with a (d) CERT-In compliance skin.** This maximizes the weighted judging criteria: Novelty (autonomy dial + citation-grounded triage + prompt-injection defense), Technical complexity (OCSF + Sigma + multi-agent + OPA policy + MITRE mapping), Feasibility (all free-tier, license-clean, demo-proven), Sustainability (open standards, no vendor lock-in), Scale of impact (CERT-In/DPDP + ₹220M breach cost + I4C fraud losses), UX (plain-English cited narratives), Future-work (deception, multi-tenancy), and Business potential (compliance-as-a-service for Indian SMEs). Confidence High that this is the optimal trade-off.

**ARCH-F07 — Cost is not a constraint; scope discipline is.** Given ~5¢/incident and free credits (Bedrock, Render, n8n, Tavily), the binding constraints are (1) the 3-week clock, (2) the safety/anti-injection story, and (3) demo realism. Spend effort there, not on cost optimization.

1. **SAFE-F04** — Build the idea around an explicit autonomy dial (Shadow → Assist → Autonomous) per action type. This is the spine.
2. **AGT-F07** — Citation-grounded triage narratives are Claude's #1 differentiator; make every verdict cite its evidence.

**Stage 2 — Scope the 3-week build to a provable core.** Build path: ingest BOTS v1 (CC0) → normalize to OCSF → Sigma detections + anomaly scores → Claude correlation/classification agents (orchestrator-worker) → citation-grounded incident narrative → OPA-gated simulated response (block IP / disable account / isolate host, mocked) → auto-generated playbook + CERT-In-format report. Demo the same chain live via Atomic Red Team in an isolated VM [DEMO-F02/F04]. Reserve Opus for correlation, use Haiku for routing, cache the schema/ruleset [AGT-F10, ARCH-F07].

**Stage 3 — Future-work slide (do NOT build now):** deception/honeypot integration [ARCH-F03] and MSSP multi-tenancy for Indian SMEs [ARCH-F05] — present as the roadmap for scale + business potential.
